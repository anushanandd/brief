# Agent guide

Brief is a personal, local-first macOS finance app (Tauri: Rust + React). [PRINCIPLES.md](PRINCIPLES.md) settles conflicts. [DESIGN.md](DESIGN.md) is how the interface looks and moves; [ARCHITECTURE.md](ARCHITECTURE.md) holds the invariants a change to providers, refresh, storage, IPC, or market data must keep, and a codemap. How a module works is in its header comment, and the code wins where a doc disagrees. [docs/decisions/](docs/decisions/) records why a choice was made; add one when you make a choice someone could otherwise reverse without knowing why.

## Commands

```sh
pnpm dev                                               # browser preview (synthetic data)
pnpm tauri dev                                         # native app
pnpm test                                              # frontend tests
pnpm check                                             # format, lint, test, build
cargo fmt --manifest-path src-tauri/Cargo.toml --check
(cd src-tauri && cargo clippy --all-targets -- -D warnings)
(cd src-tauri && cargo test)                            # from src-tauri, so .cargo/config.toml
                                                        # sends bindings to src/lib/bindings
```

Run checks in proportion to the change. Docs-only changes need none.

`git config core.hooksPath .githooks` enables the hooks: pre-commit scans staged changes for secrets (gitleaks), strings from the private denylist at `~/.brief-private/denylist.txt` (outside the repo, never committed), a regenerated golden file, and statements, databases, or files over 5 MB; pre-push runs the checks above plus binding drift. CI (`.github/workflows/ci.yml`) runs the same checks. Never bypass a hook with `--no-verify` or the `BRIEF_*` overrides from an agent session; ask.

## Rules no test catches yet

- Don't launch the native app from an agent session; it reads and writes real data.
- Result-changing settings go through `FinanceSettings` (`financeSettings(data)`, `useFinanceEdits`), never renderer storage. Lint keeps `localStorage` to `src/lib/preference.ts`; what a `preference` holds is still on you.
- Never call billed Plaid endpoints on an ordinary or background refresh.
- Don't rename or replace a SQLite file while a connection holds it; restore uses SQLite's Backup API.
- Holdings chart selection must not stop the portfolio market subscriptions.
- Never regenerate `src/data/fixtures/insights-golden.jsonl`. Edit the records a deliberate rule change affects, and say why.
- Preserve unrelated working-tree changes. Prefer the standard library and existing dependencies.

## Skills

- `regen-fixtures`: regenerating contract fixtures after a contract change.
- `finance-data`: benefit terms, tax tables, contribution limits, and document readers.

## Gotchas

- The browser preview reads `src/data/seed-view.json`, `seed-spending.json`, `seed-reports.json`, `seed-objects.json`, and `seed-activity-totals.json`, which Rust writes from `seed.json`. Integrations, edits, and Apple Intelligence exist only in the native app.
- The renderer's types in `src/lib/bindings` are generated by `cargo test` from Rust's; never edit them. After a contract change run `cargo test`, then the frontend checks.
- Insights depend on the local day; tests pass an explicit `now` and a named time zone.
- Keep Tauri crates and their npm packages on the same major.minor, and update both lockfiles together.
- `liveline@0.0.7` is patched; read [docs/liveline-patch-review.md](docs/liveline-patch-review.md) before changing it, and restart Vite afterward.
- Market sockets: keep timestamps monotonic, feeds separate, corrections repaired, hidden windows shut down, and stale data cleaned. Price ticks may coalesce; bar corrections may not drop.
- `pnpm tauri dev` signs builds through `scripts/macos-signed-runner.sh`. Brief must run from `target/debug/brief`, the path Keychain trusts.
- Don't run `cargo clean` unless necessary.
- Apple Intelligence reads about 4,096 tokens per question, so `assistant_planner` chooses which tools to offer. Read `assistant_tools`' header before adding a tool: a tool goes in three places, and an eval set checks its routing.

## Code and docs

Keep tests beside their module; assert results, unavailable states, and trust boundaries, not styling. Pin dates and use small, generic synthetic data: round amounts, invented names, no life stories, nothing copied from real records. A case that needs real data lives in `notes/` and runs only when present. Match the surrounding code. Docs say what code can't; name any doc you changed in your final response.

Comments are minimal. A module gets a short header saying what it's for; a function gets one only when its reason isn't obvious; inside code, comment only the surprising. Never narrate test data or restate the code. Write each comment as one plain sentence you'd say aloud.
